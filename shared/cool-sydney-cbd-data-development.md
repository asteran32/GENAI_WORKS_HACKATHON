# Cool Sydney — Sydney CBD 데이터 확장 개발 문서

2026-10-27 · 구현 계획 · 대상: Town Hall 분석 구역

> 이 문서는 [제품 아키텍처](cool-sydney-architecture.md)를 현재 [Cool Sydney 구현](../cool-sydney/README.md)에 적용하기 위한 작업 명세다. 아래는 목표 명세이며, 구현 현황과 차이는 다음 절에 기록한다.

## 구현 현황 · 2026-10-27

- **구현·실자료 확인:** City of Sydney 자동 계수 지점/시간별 계수·수목, OSM 원본 노드/웨이, Open-Meteo ERA5 하루를 수집하고 4개 GeoParquet와 2개 Parquet로 검증한다. `2025-01-15` 묶음에 보행 엣지 23,839개, 수목 7,887개, 계수 96행, 기상 24행이 있다. 실제 GIS 건물 버전과 함께 불변 묶음 포인터에 저장된다.
- **화면·경로 확인:** Three.js에서 보행망·수목·계수 지점을 표시하고 지도 클릭으로 두 지점을 선택한다. 최단시간 및 제한된 가중치 후보 중 저노출 경로를 비교하며, 4m 경로 표본에서 건물·가정 기반 수관 그림자를 계산한다. API의 원천·품질과 실행 ID를 표시하고 결과를 다시 읽는다. 30개 자동 테스트와 로컬 브라우저 흐름을 확인했다.
- **남은 검증·개발:** 현재 OSM 그래프는 일반 보행 노드의 약 85%가 최대 연결 성분에 속하고 나머지는 534개 작은 성분으로 나뉜다. `TreeCanopyNS`의 단위·의미, 차도 중심선/횡단 및 무장애 접근성의 현장 지도 대조, NSW 2024–25 수관 피복 교차 확인, BOM 최근 관측, 정기 보행 조사, Zetaris CBD 테이블 등록, 대표 경로 10~20쌍 수작업 대조가 필요하다. 저노출 결과는 후보 탐색이며 전역 최적 보증은 없다. 거리 계산은 현지 평면 근사로, 목표 EPSG:7856 변환은 아직 적용되지 않았다.
- **시간 해석:** City 계수 `Date`의 epoch 숫자는 `Hour` 필드 및 일중 통행 패턴에 근거해 Sydney 현지 벽시계를 표현한 것으로 해석해 UTC로 변환한다. 이 원천 의미는 제공처 문서로 추가 확인해야 한다. 서머타임 전환일은 중복·누락 현지 시각을 식별할 수 없어 가져오지 않는다.

## 1. 목표와 첫 결과물

기존 Sydney CBD / Town Hall 지도에 **유동인구 관측, 보행망, 나무, 기상**을 더한다. 사용자는 유효한 과거 여름 날짜와 시각을 선택하고, 통행량 관측 지점 및 나무를 보며 두 지점 사이의 최단시간 경로와 햇빛 노출이 적은 경로를 비교한다. 결과에는 이동 시간, 직사광 노출 시간, 자료 출처, 관측·추정·가정의 구분이 함께 나온다.

첫 구현은 현재 코드의 Node 서버, Three.js 화면, 로컬 GeoParquet/Parquet, GIS 워커를 확장한다. 장기 아키텍처의 React/CesiumJS·FastAPI·PostGIS 전환은 이 작업의 선행 조건이 아니다. 냉방 쉼터 배치 최적화, 개인별 열위험, 거리별 기온 예측은 시설 운영·수용량과 검증된 열환경 모델이 준비된 뒤의 작업이다.

완료 시 최소 데모는 다음 한 흐름을 재현해야 한다.

1. 검증된 여름 하루의 시각을 선택한다.
2. 지도에서 보행 계수 지점, 수목, 보행 구간, 건물·나무 그늘을 켜고 끈다.
3. 출발점과 도착점을 정해 두 경로를 비교한다.
4. 같은 자료 묶음으로 재실행했을 때 같은 경로·노출 지표와 출처를 얻는다.

## 2. 현재 코드 기준선

| 구성 | 현재 상태 | 이번 변경 |
| --- | --- | --- |
| 지도 수집 | `gis-store.js`가 OpenFreeMap PBF에서 6개 레이어를 수집 | 원천별 수집기를 추가하고 자료별 상태·버전을 관리 |
| 파일 계약 | `parquet.py`가 동일한 공간 형상 스키마로 6개 GeoParquet를 기록 | 수목·계수 지점·보행망용 공간 스키마와 시계열용 일반 Parquet 스키마 추가 |
| 도로 표현 | `transportation` 선형을 Three.js에서 그림 | 원본 OSM 연결 관계로 별도 보행 그래프 구축 |
| 그늘 계산 | `gis-shadow.js`가 건물과 평지 20m 표본으로 그림자 계산 | 수관을 포함하고 보행 경로 위에서 촘촘하게 표본화 |
| 실행 | `service.js`의 GIS 요청은 단일 워커로 실행하고 JSON 결과를 저장 | 자료 묶음 선택, 경로 작업, 관측 조회, 캐시·실패 상태 추가 |
| 화면 | `src/city-app.mjs`, `src/city-scene.mjs`가 건물·그늘을 표시 | 네 자료 레이어, 경로 비교, 품질·출처 표시 |

현재의 `transportation` 지도 선은 보행 가능 여부·연결 관계·횡단보도까지 보증하지 않는다. 현재 `landcover`도 개별 수목의 수고와 수관을 제공하지 않는다. 기존 합성 인구·쉼터 최적화 코드는 첫 GIS 화면의 실제 유동인구 수요로 사용하지 않는다.

## 3. 자료 범위와 출처 확인

분석 화면은 현재 `city-data.js`의 `sydney-town-hall` 경계를 따른다. 수집 범위는 자료별로 정한다. 보행망은 경계 밖에서 들어오는 경로를 탐색할 수 있을 만큼 확장하고, 그림자용 건물·나무는 태양 고도와 높이에 따른 영향 거리까지 포함한다. 기존 600m 버퍼를 모든 자료에 같은 안전거리로 간주하지 않는다.

| --- | --- | --- |

자료 접근과 라이선스는 실제 원본 다운로드 전에 각 원천의 메타데이터로 확정한다. City of Sydney 허브의 내려받기 주소·필드·최신 행, NSW 수관 파일 형식, BOM 피드 이용 조건은 수집 가능성 점검에서 기록한다. 공식 설명 페이지가 존재한다는 사실만으로 실제 행을 확보했다고 판단하지 않는다.

## 4. 데이터 계약과 저장

모든 자료는 원본을 `data/cool-sydney/raw/<source>/`에 캐시하고, 정규화 결과를 `data/cool-sydney/processed/<component>/<version>/`에 둔다. 파일을 쓴 뒤 행 수·스키마·파일 해시·재조회 결과를 확인한 경우에만 현재 자료 묶음 포인터를 원자적으로 교체한다. 한 원천의 실패는 기존 건물 지도 표시를 중단하지 않고 해당 레이어와 분석 기능의 상태로 반환한다. 경로 분석에 필요한 구성요소가 빠졌다면 경로 실행만 준비되지 않은 상태로 둔다.

공통 메타데이터는 `source_id`, `source_url`, `source_revision`, `source_hash`, `collected_at_utc`, `valid_from_utc`, `valid_to_utc`, `license`, `crs`, `units`, `method`, `quality_status`, `dataset_version`을 포함한다. 원천이 값을 제공하지 않으면 `null`과 결측 사유를 저장한다. `observed`, `survey_estimate`, `reanalysis`, `derived`, `assumed`를 구분하는 `evidence_type`을 둔다.

| 파일 | 주요 열 | 형식 |
| --- | --- | --- |
| `walk_nodes.parquet`, `walk_edges.parquet` | 노드·엣지 ID, 양 끝 노드, 길이 m, 연결 층위, 보행 허용, 계단·경사·접근성 상태, 선형 | GeoParquet |
| `trees.parquet` | 자산 ID, 위치, 수고 m, 원본 수관 치수, 모델 수관 치수·방법, 상태·품질 | GeoParquet |
| `pedestrian_sites.parquet` | 계수 지점 ID, 위치, 원본 자료 종류, 연결된 보행 엣지와 연결 품질 | GeoParquet |
| `pedestrian_counts.parquet` | 지점 ID, 관측 시각 UTC, 시간 구간, 통행 횟수, 조사 방식, 오류 표기 | Parquet |
| `weather.parquet` | 시각 UTC, 관측소·격자 ID, 기온 °C, 상대습도 %, 풍속 m/s, 일사 W/m², 값별 출처·종류 | Parquet |

공간 처리 중 거리·면적은 지역 미터 좌표계인 GDA2020/MGA Zone 56(EPSG:7856)를 사용하고, 화면 전달 시 경도·위도(OGC:CRS84)로 변환한다. 수평 좌표와 수직 높이 기준은 따로 기록한다. 시각은 UTC를 정본으로 두고 화면에서 `Australia/Sydney`로 변환한다. 서머타임 전환일의 존재하지 않거나 중복되는 현지 시각은 입력 검증에서 처리한다.

기존 `processed/current.json`은 `gis-store.js`가 `ofm-…` 버전으로 읽으므로 건물 지도의 포인터로 유지한다. 새 `processed/bundles/current.json`을 두어 자료별 버전을 참조하는 불변 묶음을 관리한다. 건물만 있는 기존 실행 기록은 계속 읽고, 새 경로 실행부터 묶음 버전을 사용한다. 형식 예시는 다음과 같다.

```json
{
  "area_id": "sydney-town-hall",
  "bundle_version": "cbd-<content-hash>",
  "components": {
    "buildings": "ofm-<hash>",
    "walk_graph": "walk-<hash>",
    "trees": "trees-<hash>",
    "pedestrian_counts": "counts-<hash>",
    "weather": "weather-<hash>"
  },
  "validation_status": "passed",
  "created_at_utc": "<ISO-8601>"
}
```

각 실행에는 묶음 버전, 원천별 해시, 계산 알고리즘 버전, 선택 시각, 가정값을 저장한다. 그림자 캐시는 건물·나무 형상과 수고·수관 가정, 시각, 표본 간격, 알고리즘 버전에 의존한다. 경로 캐시는 보행 그래프, 시작·도착 지점, 프로필, 그림자 캐시와 우회 제한에 의존한다. 계수·기상 값이 바뀌어도 변경되지 않은 공간 자료를 다시 다운로드하지 않는다.

## 5. 계산 명세

### 5.1 보행 그래프

원본 OSM 노드·웨이와 보행 태그를 수집한다. 교차점에서 선형을 분할하고 노드 공유·횡단보도·진출입·`layer`/`bridge`/`tunnel` 조건에 따라 연결한다. 화면에서 선이 교차해 보여도 서로 다른 층이면 연결하지 않는다. 차도 중심선이 보도를 대신하는 구간은 별도 품질 표기와 현장·지도 검토를 요구한다. 시청 접근성 자료는 확인 가능한 계단·승강기·경사 정보로 보강한다.

엣지 이동 시간은 길이와 명시된 보행 속도 가정으로 계산한다. `standard` 경로와 `step_free` 경로를 구분하되, 접근성 정보가 부족한 엣지는 무장애 경로라고 확정하지 않는다. 시작·도착점은 허용된 보행 구간에만 연결하고 연결 거리·방법을 결과에 남긴다. 최단시간 경로를 기준으로, 허용 우회 시간 내 후보 경로의 햇빛 노출을 비교한다. 우회 허용량은 사용자에게 보이는 입력이다.

### 5.2 나무와 경로별 그늘

실측 수관 다각형이 없는 나무는 수고와 확인된 수관 치수로 단순 수관 형상을 만든다. 수관 하단 높이·투과율은 가정과 민감도 범위로 기록한다. 원천 치수가 불명확하거나 수고가 없으면 해당 나무의 정확한 시간별 그림자를 계산한 것으로 표시하지 않는다. NSW 수관 피복 자료는 누락 가능 구역 탐색과 범위 비교에 쓰고, 개별 나무 높이의 대체값으로 쓰지 않는다.

기존 20m 그리드 그늘은 광역 개요 지표로 남긴다. 경로 노출 계산은 보행 엣지를 2~5m 간격으로 표본화하고, 출발 시각과 누적 이동 시간에 맞춰 태양 위치를 평가한다. 표본별 건물 차폐와 수관 차폐를 합치되 겹친 그늘을 두 번 세지 않는다. 결과는 `travel_minutes`, `direct_sun_minutes`, `shade_minutes`, `unknown_minutes`, `assumptions`로 반환한다. 기온 하강량이나 체감온도를 여기서 산출하지 않는다.

### 5.3 유동인구와 기상 결합

계수 지점은 위치·도로 방향·인접 엣지를 검토해 연결한다. 연결이 모호하면 자동으로 가장 가까운 엣지에 확정하지 않는다. 자동 센서 관측과 정기 조사 추정치를 방법별로 집계하고, 관측이 없는 엣지에는 수치 대신 `unobserved`를 표시한다. 전체 네트워크로 확장하는 통행량 모델은 별도 보정·검증 작업으로 둔다. 통행 횟수는 고유 인원, 지역 체류인구, 냉방 쉼터 수요와 다르다.

기상 레코드는 선택 시각과 가장 가까운 유효 시간 구간의 관측 또는 재분석 값에 연결한다. 누락 시간·관측소와 분석 구역 사이의 차이를 결과에 표시한다. 태양 위치는 날짜·좌표로 계산하고, 기상 일사 값은 별도 자료로 취급한다. 과거 유동인구와 현재 나무·건물 형상을 함께 쓰는 실행은 **현재 도시 형상에 과거 조건을 적용한 시나리오**라고 표기한다.

## 6. 애플리케이션 계약

아래 경로는 이번 확장을 위한 제안이며, 기존 `/api/gis/*`와 `/api/runs/*`의 응답 계약을 단계적으로 확장한다. `server.js`가 현재 `url.pathname`만 `dispatch`에 넘기므로 조회 매개변수를 받는 경로를 추가할 때 `searchParams` 전달을 함께 구현한다.

| 경로 | 입력·결과 |
| --- | --- |
| `GET /api/gis/datasets` | 자료별 준비 상태, 버전, 기준일, 출처, 행 수, 결측·오류 요약 |
| `GET /api/gis/observations?instant=…` | 해당 시각의 계수 지점별 유동인구와 기상 값. 관측 종류 포함 |
| `POST /api/gis/routes` | 출발·도착 경위도, 출발 UTC 시각, 보행 프로필, 우회 허용 시간 → 최단시간/저노출 경로와 지표·버전 |
| `GET /api/runs/{id}` | 기존 결과 조회 경로를 확장해 저장된 입력·자료 묶음·경로·지표·가정·검증 상태 반환 |

`/api/gis/data`의 건물·배경 지도 응답에 보행 그래프 전체와 장기간 시계열을 합치지 않는다. 화면에는 현재 범위와 시각에 필요한 축약 레이어만 전송한다. 경로 결과의 형상과 수치는 같은 `run_id`를 사용한다. 자료·프로필이 없거나 좌표가 구역 밖이거나 연결 가능한 출발점이 없으면 검증 실패 상태를 반환한다. 작업이 30초를 넘길 수 있으면 기존 작업 ID·상태 조회 패턴으로 분리한다.

Zetaris에는 검증된 Parquet의 일반 열 중심 집계를 등록한다. 초기 대상은 원천별 행 수·버전, 나무 높이 결측률, 센서별 유효 관측 건수, 경로 결과 요약이다. 공간 그래프 탐색과 그림자 광선 계산은 워커가 로컬 파일을 읽어 수행한다. NVIDIA 설명은 검증된 실행 ID와 수치만 인용하고, 자료가 없는 구간의 통행량을 만들어 내지 않는다.

## 7. 구현 순서와 완료 증거

| 단계 | 작업 | 완료를 확인할 증거 |
| --- | --- | --- |
| 0. 원천 수집 가능성 | 네 자료의 실제 내려받기·API 응답, 필드, 이용 조건, Town Hall 범위, 여름 하루의 시간 겹침 확인 | 원천 URL·라이선스·샘플 행·결측률·선택 날짜를 담은 데이터 조사표. 필수 자료가 없으면 데모 날짜·범위를 다시 정함 |
| 1. 파일·버전 계약 | 수집기 분리, 자료별 Parquet 스키마, 원본 캐시, manifest·현재 묶음 포인터 | 해시 손상 거부, 재조회 일치, 수집 실패 후 이전 검증 묶음 유지, 재시작 복구 |
| 2. 네 자료 표시 | 수목·관측 지점·보행 선형·기상 조회와 출처 표시 | 지도·시계열·데이터 상태가 실제 Parquet와 일치. 관측·모델·가정 표기가 화면에 나타남 |
| 3. 보행 경로 | 그래프 생성, 층위·횡단·계단 처리, 2개 보행 프로필 | 대표 경로 10~20쌍의 수작업 지도 대조. 끊긴 노드·잘못 연결된 지하/지상·접근성 불명 구간 보고 |
| 4. 경로 노출 | 나무 수관 가정, 시간별 경로 표본, 최단시간/저노출 비교 | 동일 입력 재현, 건물·나무 겹침 중복 제거, 표본 간격 민감도, 야간·수관 결측 사례 |
| 5. 유동인구 결합·데모 | 관측 지점 매칭, 시각별 필터, 비교 화면, Zetaris 요약 | 2025년 6월 이후 자동 관측을 실시간으로 표시하지 않음. 원천·버전·품질과 실행 ID가 화면·파일에서 일치 |

기존 `cd cool-sydney && npm test`는 모든 단계에서 유지한다. 신규 자동 검증은 수집기 페이지네이션·중복 ID, UTC/서머타임, 그래프 연결성, 경로별 거리·시간, 그늘 중복, 결측·오류 센서, 데이터 버전 불일치를 중심으로 작성한다. 실제 API 다운로드와 브라우저 지도 검수는 모의 응답 테스트와 별도의 완료 증거로 기록한다.

## 8. 개발 중 유지할 판단 기준

- 분석 구역의 모든 거리에 유동인구가 관측된 것처럼 채색하지 않는다. 관측 지점과 추정 구간은 지도 범례부터 구분한다.
- 측정한 나무 치수와 수관 모형 가정을 별도 열에 보존한다. 수관의 계절 변화와 투과율은 민감도에 포함한다.
- 건물 높이와 평지 가정의 기존 불확실성을 실행 결과에 계속 표시한다. 경계 밖 그림자가 영향을 주는지 태양 고도별로 확인한다.
- 기상 관측소 값과 과거 재분석 격자 값은 거리 수준의 기온 실측으로 설명하지 않는다.
- 원천의 이용 조건을 확인한 뒤 저장·표시·Zetaris 등록 범위를 정한다. 인증정보와 대용량 원본은 Git에 넣지 않는다.
