모드 B · 폰 + PC

폰은 촬영, PC는 큰 안내 화면

PC가 만든 세션 QR을 폰으로 열어 페어링한다. 폰의 영상은 WebRTC로 PC에 보내고, 폰이 선택한 분석 프레임은 백엔드로 직접 전송한다. AI 결과는 두 화면의 같은 세션에 전달한다.

폰 카메라 → WebRTC → PC 웹 뷰어
공통 · Web baseline

먼저 영상 위에 안내한다

Canvas로 부품 윤곽·방향을 표시한다. 평면 마커·특징점 추적 또는 사용자 선택으로 초기 정렬한다. 추적이 없으면 정지 프레임을 사용한다. Three.js는 3D를 그리는 도구이며 공간 추적은 별도로 필요하다.

선택 · WebXR

지원 기기에서 공간 AR

navigator.xr와 immersive-ar 지원을 실행 시 확인한다. 지원되는 브라우저에서만 WebXR 추적을 사용한다. iPhone Safari와 앱 WebView에서 같은 지원을 가정하지 않는다. PWA 설치만으로 기능이 추가되지 않는다. [8]

앱 · Native extension

패키징과 정밀 AR을 구분

Capacitor로 웹을 앱에 넣고, 필요할 때 Swift/Kotlin 플러그인과 네이티브 AR 화면을 구현한다. AR 프레임 추적·렌더링은 네이티브에서 수행하고 웹에는 명령·요약 상태를 전달한다. 카메라 소유권도 모드별로 전환한다. [9]

수집

제품별 자료 묶음

  • 상품 번호, 제품군, 크기·색상, 국가·언어
  • 상품 페이지, 제품 사진, 조립 PDF 전체
  • 문서 번호·개정판, 부품 목록, 도구·주의사항
  • 제품에 딸린 여러 포장·옵션·추가 설명서 연결

공식 상품 페이지의 Assembly documents가 출발점이다. 허용된 수집 범위 안에서 작업 큐·재시도·요청 속도 제한을 둔다. 문서 해시로 중복을 제거하고 개정판을 추적한다. [1]

추출·변환

그림을 조립 그래프로

  • 텍스트 추출 + OCR + 페이지 그림 분석
  • 부품 모양·개수, 나사 종류, 방향·구멍 식별
  • 조립 동작, 선행 조건, 완료 후 관찰 조건
  • 출처 페이지·그림 영역·추출 신뢰도 기록

그림 중심 설명서에는 OCR만으로 부족하다. Nemotron Omni 등 시각 모델이 구조화 초안을 만들고, 스키마 검사와 사람 검수로 확정한다.

추가 제작

PDF 밖에서 필요한 자료

  • 부품별 실제 사진과 여러 시점의 조립체 영상
  • 정확한 3D 형상 또는 측정한 단순 형상
  • 부품 좌표계, 연결 지점, 삽입·회전 방향
  • 오조립·가림·중간 상태를 포함한 평가 자료

치수와 숨겨진 면은 PDF의 2D 그림만으로 유일하게 복원되지 않는다. 확보한 CAD, 실물 측정·스캔, 수작업 모델링을 사용한다. 생성 3D는 검수 전 초안으로만 취급한다.

프로젝트 내부 파일 저장소

프로젝트 루트 기준 · 데이터 내용은 Git 제외 / 폴더 구조는 공유

data/
├── raw/manuals/       # 원본 조립 PDF
├── raw/products/      # 상품 자료·사진
├── processed/pages/   # PDF 페이지 이미지·crop
├── processed/graphs/  # 추출·검수용 그래프 JSON
├── assets/models/     # GLB/USDZ·연결점 자료
└── evaluation/        # 실물 평가 자료

예: raw/manuals/{market}/{article_id}/{revision}/manual.pdf
승인된 조립 지식과 세션의 원장은 PostgreSQL이다.

File → metadata → delivery

폰에서 로컬 자료를 읽는 경로

  1. 수집 워커가 ./data/에 파일을 기록한다.
  2. PostgreSQL에 자산 ID·상대경로·해시·제품 버전을 기록한다.
  3. Zetaris가 구조화된 조립 지식과 자산 참조를 조회한다.
  4. 브라우저는 백엔드의 /assets/{asset_id}로 파일을 받는다.

경로는 프로젝트 루트에서 계산한다. 백엔드·워커를 Docker로 옮길 때 같은 폴더를 ./data:/app/data로 마운트한다. 이 마운트와 Asset API는 구현 계획이며 현재 실행 서비스는 아니다.

PostgreSQL을 쓰는 이유: 제품–문서–부품 관계를 조회하고, 완료 이벤트와 진행 상태를 한 트랜잭션으로 기록해 이어하기를 지원한다. 단일 사용자 데모에는 SQLite도 가능하지만 팀·다중 세션 운영을 위해 PostgreSQL을 제안한다.

Fast loop · On device

브라우저에서 추적·표시

30–60fps 목표 · 측정 전

웹은 video + Canvas로 부품 강조·방향을 그린다. 클라이언트 추적기로 위치를 갱신하고, 검증된 3D pose가 있을 때 Three.js 표시를 사용한다. 앱에서는 AR 어댑터를 추가할 수 있다.

렌더링 fps와 AI 호출 주기는 다르다. 부품 추적이 끊기면 화살표를 숨기고 정지 프레임 안내로 전환한다. 공간 고정 AR은 지원·정렬이 확인된 모드에서만 제공한다.
Reasoning loop · Backend

변화가 있을 때만 AI 판단

1–3초가이드 갱신 p95 목표 · 측정 전

선택한 프레임·짧은 관찰 묶음을 보내 상태를 추정한다. 상태 변화·사용자 질문·불확실성 발생 시만 다음 행동을 다시 계산한다.

클라우드 VLM을 매 프레임 호출하지 않는다. 실제 기기·네트워크·모델로 지연과 호출 비용을 측정한 뒤 샘플링 주기를 정한다.
Recovery loop · Verification

“완료”는 관찰로 확인

관찰 + 확인

연속 관찰에서 연결 관계를 확인하고 그래프를 갱신한다. 보이지 않는 체결 상태는 확대 촬영이나 사용자 확인을 요청한다.

나사를 가져다 댄 장면만으로 조임·체결 토크·구조 안전을 확정하지 않는다. 판단 근거가 부족하면 다음 단계 진행을 보류한다.

모델·Zetaris 호출은 공통 백엔드에서 수행하고 키는 서버 .env에 둔다. 촬영 폰이 선택 프레임을 백엔드로 전송한다. PC 연결 모드의 전체 영상은 WebRTC로 전달하며 연결이 끊기면 신규 완료 판정을 보류한다.

Nemotron은 NVIDIA의 AI 모델 계열이다. Super는 현재 설정된 텍스트 판단 모델이며, Nano Omni는 이미지·영상 이해 후보다. NVIDIA 공개 API를 사용할 수 있지만 현재 키가 없어 두 모델 모두 실제 호출을 검증하지 않았다. 작은 나사 인식·정확한 좌표는 별도 평가가 필요하다. [4][5]

Omni는 공식 모델 카드에서 영어 지원을 명시한다. 내부 관찰은 영어·구조화 ID로 받고 한국어 안내는 검수된 템플릿으로 시작한다. Meterless의 Omni 제공 여부·키 발급 경로는 미확인이다. 두 모델 분리는 설계 선택이며 응답 품질·지연을 비교해 확정한다.

Deterministic checks

모델 출력 뒤에 반드시 두는 검증

  1. 제품·문서 버전 일치: 다른 크기나 개정판의 단계가 섞이지 않았는가.
  2. 실행 가능한 동작: 모든 선행 조건이 확인됐고 필요한 부품이 있는가.
  3. 공간 근거 존재: 연결점·방향·단위가 검증된 자산에 있는가. 없으면 정밀 AR을 표시하지 않는다.
  4. 현재 관찰과 일치: 오래된 프레임에 대한 응답은 버린다. 가구가 움직이거나 추적이 끊기면 재정렬한다.
  5. 단계 진행 검증: 관찰된 연결, AI 추정, 사용자의 확인을 별도로 기록한다.

웹 기본 명령은 frame=image_normalized와 원본 프레임 크기·회전·seq를 포함한다. Canvas는 video의 crop·회전·미러링을 반영하고 최신 추적 결과에만 그린다. 판단 신뢰도만 높다고 정밀 화살표를 표시하지 않는다. 부품 식별·추적 품질·연결 위치의 검증 여부도 함께 만족해야 한다.

05 / ALL PRODUCTS, VERIFIED COVERAGE

전체 IKEA 제품으로 확장하는 방법

전 제품을 담을 수 있게 데이터 구조를 설계하고, 정밀 AR 지원은 제품군별 검증을 거쳐 늘린다. 수집량과 실제 지원 범위를 따로 측정한다.

L1자료 확보

상품·설명서·개정판 확인. 원문 안내 제공.

L2조립 지식 검증

부품·순서·선행 조건 확인. 단계별 안내 가능.

L3중간 상태 인식

여러 실제 중간 상태에서 인식 성능 통과.

L4정밀 AR 검증

연결 위치·추적·오정렬 대응까지 실물 평가 통과.

국가별 상품 카탈로그를 분모로 제품군·SKU·문서 개정판별 지원 수준을 표시한다. 단종 제품은 공개 설명서가 없을 수 있어 고객 제공 문서나 별도 확보 경로가 필요하다. 조립이 필요 없는 제품은 카탈로그에서 구분한다. [2]

PHASE 01 / FIRST VERTICAL SLICE

한 제품 · 휴대폰 웹 MVP

단순한 제품 1개로 PDF → 조립 지식 → 폰 카메라 → 웹 안내 → 완료 확인을 연결한다.

  • 부품 사진·연결 지점은 직접 준비
  • 상품 번호·바코드·수동 선택으로 제품 확정
  • 첫 5~10개 동작과 중간 시작 시나리오
  • HTTPS 모바일 웹 · 후면 카메라 · Canvas 안내
  • 수동 선택·임시 마커로 초기 부품 정렬 보조
  • Zetaris 근거 조회 + Nemotron 판단
통과 기준설명서를 찾지 않고 중간 상태에서 다음 연결을 수행. 모호한 관찰에서는 확인을 요청하고 잘못된 위치에 화살표를 표시하지 않음.
PHASE 02 / PRODUCT FAMILY

PC 연동 · 앱 패키징

웹 흐름을 검증한 뒤 QR 카메라 연결과 Capacitor 앱을 추가한다. 공통 화면·API 계약은 유지한다.

  • WebRTC 페어링 · STUN/TURN · 재연결
  • Capacitor 권한·카메라·앱 복귀 실기기 시험
  • 정밀 AR 필요 시 별도 네이티브 어댑터
  • 실물 영상 기반 부품 인식·pose 평가
  • 왼쪽/오른쪽 판, 비슷한 나사 구별
  • 가림·역광·다른 방·재시작 시험
  • 정상·오조립·재작업 관찰 데이터 확보
  • 지원 SKU별 검수·회귀 테스트
통과 기준iOS·Android 브라우저와 앱에서 상태 복구·카메라 권한·명령 유효성 통과. 검증된 공간 모드만 정밀 AR로 표시.
PHASE 03 / CATALOG SCALE

전 제품 수집과 지원 운영

허용된 공식 데이터 공급·수집 경로를 확보하고 개정판별 지원 품질을 관리한다.

  • 국가·옵션·세트 구성까지 카탈로그 연결
  • 문서 변경 감지 → 영향 분석 → 재검수
  • 검증된 상태 그래프와 AR 자산만 배포
  • 지원하지 못하는 SKU는 원문·음성 안내
  • 관찰 실패 사례를 제품 검수 큐로 연결
통과 기준카탈로그 수집률과 L2/L3/L4 지원률을 별도로 공개. 업데이트가 기존 조립 세션의 그래프 버전을 바꾸지 않음.

처음부터 측정할 지표

  • 중간 상태 복원: 연결 관계 precision/recall, 후보 상태 정확도, 미확인 상태 감지
  • 안내 정확도: 잘못된 부품·연결점 선택률, 잘못된 완료 판정률
  • AR 품질: 실측 위치·각도 오차, 추적 실패율, 이동 후 재정렬 시간
  • 제품 가치: 다음 행동까지 걸린 시간, 재작업 횟수, 설명서로 돌아간 횟수
  • 운영: p95 응답 시간, 세션당 추론 비용, 지원 수준별 SKU 비율

착수 전에 확정할 세 가지

  1. 실물 제품: 팀이 확보할 제품 1개와 실제 중간 조립 상태들을 정한다.
  2. 촬영 장치: iOS Safari·Android Chrome에서 웹 촬영을 확인한다. 폰 단독 / 폰 카메라 + PC 화면 중 데모 모드를 정하고 거치 방식을 준비한다.
  3. 정밀도 목표: 판과 구멍 안내인지, 작은 나사 끝까지 안내할지 구분하고 제품별 허용 위치·각도 오차를 정한다.

최초 구현의 핵심 가설은 “설명서 탐색 없이 중간에서 이어갈 수 있는가”다. 제품 수를 늘리는 작업은 이 경험의 검증 이후에 병행한다.
