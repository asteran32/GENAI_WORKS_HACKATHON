도시의 그늘을 계산하고,
냉방이 닿는 범위를 넓히다.

건물·나무·태양으로 시간별 그늘을 계산한다. 보행 경로와 냉방 시설을 연결해, 같은 예산으로 더 많은 취약 주민이 쉴 수 있는 배치를 비교한다.

THE PRODUCT QUESTION

“이 시간에 쉼터 3곳을 열면,
누구의 접근 공백이 줄어들까?”

날짜·시간·시설·차양을 바꾸고 기준안과 대안을 비교한다. 지도에는 그늘과 경로를, 지표에는 도달·수용 가능한 주민과 남는 공백을 보여준다.

공개 명세·참조 구현을 활용한 어댑터를 제안한다. 별도 구현과 행사 통합 요건 확인이 필요하다.

03 / GIS INPUTS

건물 윤곽만으로는 부족하다

실제 높이·수관·지형과 보행 경로가 있어야 그늘이 주민의 이동에 미치는 영향을 계산할 수 있다.

자료필요한 속성쓰임확보·검증할 사항
건물·지형윤곽, 실제 지상 높이, DEM/DSM, 수직 기준건물·지형 차폐지역별 확보 필요. 계획상 허용 높이는 실제 높이를 대체하지 않음
나무수관 범위, 높이, 형상, 투과율시간별 나무 그늘공개 수관 피복만으로 정확한 높이 추정 불가. 높이 확보 또는 가정 범위 필요
보행망보도, 횡단보도, 계단, 경사, 시설 출입구이동 시간·접근 가능 여부한 구역을 선정해 연결성·보행 허용·출입구 확인
인구·취약성SA1 경계·인구, 집단별 통계, HVI취약 집단별 접근 공백HVI는 Greater Sydney 자료. 경계 연도·집단 중복 확인
시설냉방, 운영시간, 수용량, 운영비, 접근성실제 사용 가능한 쉼터위치만으로 사용 가능 판정 금지. 미확인 값은 시나리오 가정
시간·기상날짜, 시간대, 기온·습도·바람·일사태양 위치·상황 조건태양 계산과 기상 관측 구분. UTC 저장, Australia/Sydney 표시
NSW의 공개 수관 피복과 상세 나무 높이 자료는 접근 조건이 다르다. 높이가 없으면 가정 범위를 표시한다. HVI는 Greater Sydney의 SA1 단위 지수이며 실시간 기온이나 NSW 전역의 자료로 해석하지 않는다.
04 / BUILD & DEPLOY

작은 구역에서 끝까지 연결한다

로컬 API·워커·PostGIS와 기존 Zetaris Docker를 연결한다. 모델 추론은 외부 엔드포인트를 사용하도록 제안한다.

LOCAL FIRST

프로젝트 내부에 GIS와 결과 저장

data/cool-sydney/
├── raw/          원본 GIS·시설·인구
├── processed/    정규화·보행망·지도 자산
├── shadows/      시간·형상별 그늘 캐시
└── runs/         입력·결과·검증 스냅샷

제안 경로 · 파일은 Asset API로 제공. PostgreSQL에 작업 상태와 결과 원장을 기록하고 H-MEM은 관련 기억을 검색한다. AWS·S3는 전제로 하지 않는다.

IMPLEMENTATION ORDER

구현 완료를 확인하는 순서

  1. 구역 선정과 GIS 확보 → 높이·형상·출처 검사
  2. 태양·그늘 지도 → 몇 시점의 독립 비교
  3. 보행 접근성과 시설 배치 → 예산·수용량 검사
  4. Zetaris·H-MEM·Nemotron → 실제 호출과 수정 기록
  5. 지도·지표·근거 통합 → 재현 가능한 데모
그늘이 있다고 냉방 수요가 사라지는 것은 아니다. 첫 버전은 직사광 노출·이동 시간·도달/수용 가능한 인구를 계산한다. 그늘 면적을 온도 감소량으로 바꾸거나 실제 건강 피해 감소로 표현하지 않는다. 이 문서는 설계이며 데이터 확보·컨테이너 정상 실행·스폰서 연결을 새로 검증하지 않았다.
