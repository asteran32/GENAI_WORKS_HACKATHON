# Cool Sydney — 디자인 시스템 & UI 컴포넌트 스펙

> 콘셉트: **Architectural Canvas / Precision Engineering CAD.** 인쇄용 도면처럼 밝고 정갈한 바탕 위에, 데이터만 진한 잉크로 올린다.
> 구현: [src/city.css](src/city.css) (토큰 · 컴포넌트), [src/city-scene.mjs](src/city-scene.mjs) (3D 캔버스), [src/city-app.mjs](src/city-app.mjs) (차트 · 상호작용).

## 0. 이 프로젝트에 맞춘 해석

원본 가이드는 교통·에너지·인구를 다루는 범용 도시 시뮬레이터를 전제한다. Cool Sydney가 실제로 가진 데이터는 **건물 형상·높이, 태양 위치, 그늘 비율(서버 광선 교차)** 이다. 존재하지 않는 데이터를 화면에 꾸며 넣지 않는다는 원칙에 따라 가이드 요소를 아래처럼 대응시켰다.

| 가이드 요소 | Cool Sydney 대응 | 근거 |
| --- | --- | --- |
| Past–Present (실선) | **검증값**: 서버 LoD1 광선 교차, 20 m 표본 | 1회 약 17초, 신뢰 기준값 |
| Predicted Future (점선) | **추정값**: 화면 래스터 추정 (스윕 풋프린트) | 1스텝 약 60 ms, 서버 대비 +0.1~0.5%p |
| Scenario (Normal, Heavy Rain…) | **하지 / 분점 / 동지 / 관찰일** | 그늘을 결정하는 유일한 조건은 날짜·시각 |
| Baseline vs Predicted | **시나리오 vs 기준 날짜** (같은 시각) | Δ는 %p(퍼센트포인트) |
| Delta Zone | 두 곡선 사이 해칭 영역 | 하루 중 차이가 큰 시간대가 한눈에 보임 |
| 교통·에너지·인구 파라미터 | 표시하지 않음 → "다음 분석에 필요한 자료 · 미연결" | 허위 데이터 금지 |

## 1. 디자인 시스템 규칙

### 1.1 컬러 (Light mode, HEX)

| 역할 | 토큰 | HEX | 용도 |
| --- | --- | --- | --- |
| 표면 | `--bg-white` | `#FFFFFF` | 카드, 타임라인, 툴팁 |
| | `--bg-canvas` | `#F8FAFC` | 3D 배경, 바탕, 안개 |
| | `--bg-panel` | `#F1F5F9` | 좌·우 패널, 미터 트랙 |
| 선 | `--line-grid` | `#E2E8F0` | 방안지 그리드, 내부 구분선 |
| | `--line` | `#CBD5E1` | 구획 테두리, 500 m 주 그리드 |
| | `--line-strong` | `#94A3B8` | 호버 테두리, 툴팁 |
| 글자 | `--ink` | `#0F172A` | 본문, 수치, 주 버튼 |
| | `--ink-2` | `#334155` | 보조 본문 |
| | `--ink-3` | `#64748B` | 라벨, 축, 힌트 |
| 데이터 | `--data-verified` | `#1D4ED8` | **검증값** — 실선, 채운 점, 지도 그림자 면 |
| | `--data-verified-deep` | `#1E40AF` | 검증 표본 점(지도), 섹션 번호 |
| | `--data-estimate` | `#0D9488` | **추정값** — 점선 |
| | `--data-baseline` | `#64748B` | **기준 날짜** — 가는 도트선 (맥락선) |
| 상태 | `--ok` / `--warn` / `--crit` | `#059669` / `#D97706` / `#DC2626` | 상태 전용 · 항상 텍스트와 함께 |

검증: verified `#1D4ED8` ↔ estimate `#0D9488` 쌍은 dataviz 검증기에서 라이트 표면 기준 명도 밴드, 채도, CVD 분리(ΔE 20.7), 일반 시각 분리(ΔE 22.6), 대비를 모두 통과했다. 기준선은 계열이 아닌 **맥락선**이므로 회색을 쓰고, 선 모양(도트)과 직접 라벨로 구분한다.

**규칙**
- 데이터 색은 데이터에만 쓴다. 크롬(버튼·패널)은 잉크와 회색만 쓴다. 주 버튼은 `--ink` 채움이다.
- 상태 색(amber/crimson)은 경고·오류 전용이다. 태양 아이콘처럼 장식에 쓰지 않는다.
- 글자는 계열 색을 입지 않는다(예외: 차트 직접 라벨은 어둡게 한 단계, `#0F766E`, `#475569`).
- Δ 배지: 그늘 증가 ▲ = ok(초록), 감소 ▼ = warn(주황), 변화 없음 = 중립. 화살표와 부호를 함께 써서 색만으로 판단하지 않게 한다.

### 1.3 그리드 · 간격 · 형태

- 간격 단위 4 px: `4 · 8 · 12 · 16 · 20 · 24 · 32`. 패널 내부 블록 패딩은 `16 × 20`.
- 레이아웃: `48px` 헤더 / `288px` 좌 패널 / `1fr` 캔버스 / `344px` 우 패널 / `188px` 타임라인(캔버스 열만 차지).
- 방안지: 캔버스 바탕 CSS 24 px 그리드(`#E2E8F0`), 3D 지면 100 m 보조 / 500 m 주 그리드.
- 모서리 반경 2 px. 그림자 없음. 구획은 1 px 선과 면 대비로만 나눈다.
- 같은 묶음의 셀(시나리오 2×2, KPI 2×3, 세그먼트, 지도 도구)은 `gap:1px` + 선 색 배경으로 **헤어라인 그리드**를 만든다.
- 반응형: ≤1180 px 패널 축소, ≤980 px 1열(캔버스 → 타임라인 → 조건 → 분석), ≤560 px 나침반·보조 정보 숨김.

### 2.2 시뮬레이션 조건 입력

- **Scenario Selector** (`.scenario-grid`, 2×2, `role=radiogroup`): 카드마다 이름 + mono `MM-DD · 남중 NN°`. 선택지가 데이터(남중 고도)를 함께 보여주므로 고르기 전에 차이를 예상할 수 있다. 선택 상태: `--info-bg` 배경, 1 px 파랑 inset 테두리, 우상단 6 px 사각 마커.
- **Date field**: 직접 입력 시 `관찰일` 카드가 선택 상태가 된다.
- **Baseline select**: 시나리오 날짜 3개 중 선택(기본 하지 12-21).
- **Toggle** (`.switch`): 범례 견본 12 px + 라벨 + 28×16 스위치(켜짐 = 잉크). 레이어: 건물, 그림자 투영, 검증 표본, 도로·녹지·수면. 견본은 지도 범례와 같은 그림을 쓴다.
- **Slider**: 시각 슬라이더 하나만 쓰고 타임라인으로 옮겼다(조건 패널에 중복 두지 않음).
- **Actions**: `이 시각 서버 검증 계산`(보조 버튼), `관찰 조건 기억하기`(quiet).

### 2.3 예측 데이터 비교 카드

**Hero KPI 카드** — 이 화면의 기준값.
- 상단 상태 pill: `● 검증 · 14:00`(파랑) / `— 추정 · 검증 대기`(청록) / `서버 계산 중`(깜빡임) / `야간` / `오류`.
- 값 44 px mono. 검증이면 `--ink`, 추정이면 `--ink-3`로 낮춰서 아직 확정 값이 아님을 표시한다.
- 미터: 파랑 채움 = 검증값, 청록 세로 눈금 = 추정값. 두 값의 차이가 막대 위에서 바로 보인다.
- 보정 행: `‑‑ 추정 11.4% · 서버 대비 +0.1%p`.

**시나리오 vs 기준 카드** (Baseline vs Predicted)
```
시나리오 vs 기준                 [▲ +29.7%p vs 하지]
‑‑ 동지 · 06-21                              41.2%
▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬ (청록 대시 막대)
⋯ 기준 하지 · 12-21                           11.5%
▪▪▪▪▪ (회색 도트 막대)
같은 시각 14:00 · 화면 추정 모델 · 그늘이 많을수록 ▲
```
- 두 값 모두 같은 모델(추정)이어서 공정하게 비교할 수 있다. 검증값과 섞지 않는다.
- 막대 패턴은 차트 선 모양과 같다(대시 = 추정, 도트 = 기준).

**KPI 그리드 (2×3)**: 태양 고도, 방위각(+8방위), 10 m 건물 그림자 길이, 일조 시간, 주간 평균 그늘(추정), 최소 그늘 시각(추정, 가장 많이 노출되는 시각). 단위는 `small`로 낮춘다.

## 3. 데이터 시각화 가이드라인

### 3.1 차트 유형 선정

| 질문 | 형태 | 이유 |
| --- | --- | --- |
| 지금 그늘은 몇 %인가 | Hero 숫자 + 미터 | 한 값이 핵심이면 차트보다 숫자가 빠르다 |
| 하루 동안 어떻게 변하나 | 선 차트 (x = 0–24시, y = %) | 연속 시간 변화. 밝은 바탕에서 2 px 선이 가장 선명하다 |
| 기준과 얼마나 다른가 | 같은 축 위 두 번째 선 + Δ 해칭 | 이중 축 없이 한 척도에서 비교한다 |
| 두 시나리오의 현재 값 | 나란한 막대 2개 | 길이 비교가 각도·면적보다 정확하다 |
| 태양 위치 | 극좌표 나침반 (반지름 = 90° − 고도) | 방위와 고도를 지도 방향 그대로 읽는다 |

- 축은 하나만 쓴다. y축 최댓값은 10% 단위로 올림하고 눈금은 0 · 중간 · 최대 3개만 둔다.
- 범례는 타임라인 상단에 항상 둔다. 곡선 2개에는 두 곡선이 가장 많이 벌어진 시각에 직접 라벨을 단다.
- 검증 = 실선 + 채운 점, 추정 = 점선, 기준 = 도트선이다. 색과 선 모양을 함께 바꿔서 흑백 인쇄나 색각 이상에서도 구분된다.

### 3.2 3D 캔버스 레이어와 대비

아래에서 위로 쌓는 순서(Y 오프셋은 z-fighting 방지용 실거리):

| # | 레이어 | 표현 | 대비 원칙 |
| --- | --- | --- | --- |
| 0 | 바탕 + 도면 그리드 | `#F8FAFC` 면, 100 m `#E2E8F0` / 500 m `#CBD5E1` | 가장 약함 |
| 1 | 도로 · 녹지 · 수면 | 회청 `#B4BFCC`–`#E0E5EB`, 연녹 `#D5E3D8`, 연청 `#CDDEEB` | 채도 ≤ 0.15, 데이터 파랑과 겹치지 않게 |
| 2 | **그림자 투영** | `#1D4ED8` 20% 면, 스텐실로 겹침 1회만 칠함 | 데이터 잉크 · 시각 변경에 즉시 반응 |
| 3 | **검증 표본** | `#1E40AF` 5 m 점(20 m 격자) | 서버가 그늘로 판정한 지점. 다른 시각으로 이동하면 숨김 |
| 4 | 건물 매스 | 높이 4단계 모노톤 `#EEF2F6` → `#C3CDD8`, 슬레이트 외곽선 55% | 높을수록 진하게. 색상(hue) 없이 깊이만 표현 |
| 5 | 연구 범위 | 파랑 점선 사각형 | 분석 경계 |
| 6 | 호버 하이라이트 | 지붕·바닥 외곽선 `#1D4ED8`, 깊이 테스트 끔 | 가장 강함 |
| HUD | 제목, 시각, 도구, 나침반, 범례, 상태바 | 흰 카드 + 1 px 선 | 지도 위에서도 읽히도록 불투명도 0.88–1 |

- 톤 매핑은 Neutral을 쓴다. ACES는 흰색과 파랑의 색을 바꿔 토큰과 어긋난다.
- OSM 원색 외벽은 쓰지 않는다. 건물은 맥락이고 색은 데이터에만 쓴다.
- 야간에도 조명을 크게 낮추지 않는다. 그늘 레이어가 꺼지는 것으로 야간을 표현한다.

### 3.3 마이크로 인터랙션

- **건물 호버 툴팁**: OSM ID, 높이, 하부 높이, *이 시각 그림자 길이와 방향*, 높이 출처, 타일. 흰 카드에 `--line-strong` 테두리를 두고 포인터를 따라가되 캔버스 경계 안에 머문다.
- **수치 보간**: KPI·비교 값은 280 ms ease-out cubic으로 바뀐다. 미터 막대는 400 ms. `prefers-reduced-motion`이면 즉시 바뀐다.
- **즉시 반응 / 지연 검증**: 시각을 바꾸면 그림자, 나침반, 추정값이 같은 프레임에 바뀌고, 서버 검증은 600 ms 디바운스 뒤 실행된다. 서버가 바쁘면(429) 오류로 표시하지 않고 재시도한다.
